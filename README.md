# 网络抓包任务操作说明

## 实验任务

应用有任务 A—H。每个按钮都会实际执行一种网络操作，但界面不公布操作名称和业务结果。

你的任务是：捕获报文，判断操作，并用报文编号、字段和时序证明自己的结论。单凭端口号或报文数量猜答案不够。

## 运行环境

- Windows 10 / 11，具备 .NET Framework 4.x。程序使用系统自带框架，不需要 Python、浏览器服务或额外项目依赖。
- 抓包另需安装 Wireshark 和 Npcap。
- 下载并双击“网络操作盲盒.exe”。
- 不需要连接互联网。所有任务都在 127.0.0.1 上产生真实的本机通信。
- 程序启动时准备本机服务，点击按钮后才产生任务请求。无需修改系统 DNS、代理、网关或防火墙。

## 每个任务都按这 6 步进行

1. 打开 Wireshark，选择名称包含 **loopback** 的回环接口，通常显示为 “Adapter for loopback traffic capture”。
2. 开始捕获。注意：不是选择 Wi-Fi 或以太网接口。
3. 点击应用中的一个任务按钮，记下任务编号和开始时间。不要连续点击多个任务。
4. 应用提示操作结束后，等待约 1 秒，再停止 Wireshark 捕获。
5. 点击“复制显示过滤器”，将内容粘贴到 Wireshark 上方的**显示过滤器**栏，按 Enter。
6. 分析报文，把抓包另存为“学号-任务编号.pcapng”。建议使用“导出指定分组”并只导出当前显示的任务报文。

显示过滤器不是捕获过滤器，两者语法不同。先完整捕获短时间的实验流量，再用显示过滤器筛选。

重复任务之前，先保存上一次捕获，再开始一份新的捕获。同一按钮可以重复执行，任务含义不变，但端口、时间、序号等具体值可能变化。

## 分析时关注什么

- 发生通信的地址和端口是什么？
- 报文使用什么协议？依据是什么？
- 先后发生了哪些事情？有没有先建立连接？
- 请求中出现了什么名字、路径、方法或数据？
- 对方返回了什么？这能说明什么，不能说明什么？
- 操作在业务层面成功了吗？不要把“应用按钮执行完成”当成“业务一定成功”。

可以展开 Wireshark 的协议树，或对相关报文使用“追踪流 / Follow Stream”。一次 TCP 发送、一次读取、一个 TCP 段和一个 HTTP 消息并不必然一一对应。

## 提交内容

1. 每个被要求完成的任务的一份抓包文件(.pcapng)。
2. 分析记录：任务编号、操作判断、关键报文编号、关键字段、解释。

应用下方可填写分析，点击“保存分析记录”导出文本。可以另用“实验记录模板.md”完成报告。

## 常见问题

**一个包都没有？**  
检查是否先开始捕获、是否选中了回环接口、Npcap 是否已安装，以及捕获权限是否允许。重新启动应用后，应重新复制显示过滤器。

**只看见 TCP 或 UDP，看不见更高层协议？**  
在应用中点击“抓不到包？”，按提示将当前使用的端口通过“分析 → 解码为（Decode As）”关联到相应协议。正常情况下，程序优先使用常见端口，冲突时会自动换端口。

**没有普通以太网头或 MAC 地址？**  
本实验使用回环通信，没有经过实体网卡。不要强行在这些报文中寻找以太网 MAC 或 ARP。Wireshark 可能显示 NULL/Loopback 等链路层类型。

**不同同学捕获的报文数不一样？**  
这是可能的。操作系统、TCP 分段、重传、卸载机制和捕获环境都会影响报文表现。请解释实际证据，不套用固定包数。

**按钮提示“本轮未完成”？**  
这表示程序自身未完成预期任务。记录提示，重新执行一次；若持续发生，请联系教师。对于本来要观察失败现象的任务，程序正常情况下仍会提示“操作已完成”。

## 结束实验

保存报告和抓包，再关闭应用窗口。
